# 性能优化详解

两层的优化：**引擎层面**（怎么把成千上万局塞进 GPU/DCU 喂给 PPO——宏观架构决策）和**算子层面**（单个算子怎么写才不拖后腿——微观实现技巧）。

实测结果：
- **JAX + ViT（7.46M 参数，Patch 4，14 通道输入）**：
  - 单机 8 卡 DCU：**162,586 ~ 254,706 SPS**（16384 环境，256 步采样）
  - 12 机 × 2 卡 = 24 卡集群（Local SGD K=32）：峰值达到 **466,000 SPS**（78624 环境，46.6 万步/秒）
- 历史对照（8 月初原型，PyTorch + MLP 36~41k SPS）已彻底作为废弃基线归档。

---

## 一、引擎层面（宏观）：高并发仿真的搭建

### 1. 并行度模型：N 局关卡整批并行，非角色级并行

一局里只有 2 到 4 个角色，把角色并行化最多拿到 4 路，无法满足现代加速器计算密度。
真正的并行度来自**同时推进上万个独立关卡**（生产配置 `--num-envs 16384 ~ 78624`）：

```
一个逻辑单元 = 一个完整对局关卡（含内部 2 名角色）
GPU/DCU 一次推进 = 16384 至 78624 个独立关卡
```

在 JAX 架构下，环境状态全部封装为固定维度的全局张量，并通过 `jax.vmap` 与 `lax.scan` 完成时序展开，**全程零 Python 循环、零动态分支**。静态计算图完全规避编译开销与 Host-Device 交互抖动。

### 2. 纯张量化与 14 通道状态感知

观测张量直接在加速器显存中通过张量切片生成，避免 CPU 与 GPU 之间来回搬运：
- 空间维度：14 通道 × 13 行 × 15 列（含墙体、障碍、泡泡倒计时、火力覆盖、可推箱等）。
- 状态维度：24 维紧凑全局向量（速度、火力、泡泡存量、存活状态等）。
- 数据类型统一使用紧凑整型与浮点，显存开销与吞吐达到最佳平衡。

### 3. JAX 纯函数式端到端 JIT 编译

整个仿真与强化学习训练链路（采样 Rollout -> GAE 计算 -> PPO 更新 -> 跨卡有损参数同步）全部被 `jax.jit` 编译为单一 XLA 执行体。
- 仿真状态在显存中就地更新，无需脱离计算图。
- 神经网络前向、反向传播与优化器步进无缝衔接，消除了传统强化学习中环境引擎与深度学习框架之间的数据拷贝损耗。

### 4. 显存守卫与峰值内存规避

PPO 单个 minibatch 的激活张量是最大内存开销项：`minibatch = num_envs × rollout_steps / minibatches`。
- 在大 batch 训练与 Local SGD 扩展下，针对大 GEMM 激活显存设置安全护栏（如限制单批最大样本容量），杜绝跨机运行时意外触发 OOM。
- 关键状态与参数支持轻量级定期快照落盘，保证长期训练稳健。

### 5. 各阶段训练吞吐演进实测（DCU 集群）

| 架构与阶段 | 硬件规格 | 环境规模 | 骨干模型 | 实测平均 SPS | 耗时与效率 |
| :--- | :--- | :--- | :--- | :--- | :--- |

## 二、算子层面（微观）：单个算子怎么写才快

### 1. 危险图用定向探测（Gather）代替散弹写入（Scatter）

直觉写法：遍历每个泡泡向四个方向 scatter 写入何时会被爆炸覆盖，导致多个泡泡的火焰写到同一网格，需要原子操作或显存互斥冲突处理。
反向优化：**每个网格自身向四个十字方向看出去 blast 格**，定向提取遇到的所有泡泡中最早引爆的时间。读操作完全共享、写操作完全独占，**零原子锁、零额外缓冲**。虽然存在邻近网格的重复读取，但在 L1/L2 缓存机制下命中率极高，吞吐显著领先。

### 2. 连锁爆炸：固定轮数同步收敛，无动态分支

若使用 CPU 动态 BFS 队列，会引入动态内存分配与线程间不等长执行，导致 GPU 计算严重空转。
这里设计为**定轮同步传播**：每一轮读取上一轮的触发状态并写入本轮覆盖区，最多迭代固定轮数（`max_chain=8`）。连锁提前结束时空跑轮次只产生空覆盖，计算结果与动态版本逐位一致，但保持了完全静态的执行时间与 XLA 计算图兼容性，彻底消除最坏分支等待。

### 3. 可推箱机制张量化：格级计时与二维精确索引

推箱玩法涉及前缘格判定、接触蓄力计时与阻挡校验：
- 计时绑定在箱子格（per-cell push_t）：支持玩家走开计时保留，被阻挡或被炸即时清零。
- JAX 写入保护：必须采用二维显式索引 `.at[pr, pc]` 进行掩码写入，规避一维展平索引在二维数组中静默截断（clamp）的严重隐患。
- 箱子属性与阻挡判定无缝并入地图物理层，零动态分支。

### 4. 合法动作掩码作用在 Logits 上

掩码若在概率层面乘以 0，在极端情况下会导致全零分布，Softmax 计算时会产生 NaN 进而污染整个网络权重。
优化方案：将掩码转化为负无穷（`-inf`）直接加在 Logits 上。结合移动与放泡双头因子化解耦架构，移动原地停留与不放泡恒合法，保证 Logits 永远存在合法取值，彻底消除数值异常根源。

### 5. 纯张量化合法动作采样，零 CPU 往返

在 Bot 陪练与环境探索采样中，利用掩码的前缀和技巧（`cumsum`）将合法项映射至离散区间，仅通过加速器上的随机均匀数与前缀和比较直接定位动作索引。
万级并发环境下的采样完全在加速器内部闭环，杜绝任何同步拉回 Host 端（`.item()` 或 `.cpu()`）的操作，避免总线往返拖死训练。

## 三、架构定型总结

项目在架构演进中彻底淘汰了早期的 CPU 动态队列与 PyTorch 原型：
1. **仿真器与网络一体化**：全链路采用 JAX 函数式张量设计，消除仿真与网络更新之间的序列化鸿沟。
2. **算子纯张量化无分支**：危险图 Gather 探测、定轮连锁爆炸与合法掩码保证了静态计算图编译优化。
3. **分布式通信延迟屏蔽**：结合 Local SGD 有损同步，成功在国产海光 DCU 集群上释放出 46.6 万 SPS 的工程极限。
