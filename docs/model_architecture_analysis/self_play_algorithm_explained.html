深入浅出：QQTang 的 Multi-Agent Self-Play 强化学习算法解析

用你熟悉的 PPO 作为基准对比，拆解对方的基础强化学习算法（MAPPO / APPO）与博弈演化机制（Population Self-Play）。

一、 核心结论：其实对方用的底层算法也是 PPO 族！

一句话大白话：
你用的标准 PPO 通常是“单智能体 / 简单同步 PPO”；而对方用的是 异步多智能体 PPO (Asynchronous MAPPO)，外层加上了种群自博弈（Population-based Self-Play）机制。

很多初学者会把“算法（Algorithm）”和“训练范式（Paradigm）”混淆：

  • 基础强化学习算法（优化器层）：是 MAPPO (Multi-Agent PPO) / APPO (Asynchronous PPO)。负责回答：“这一批轨迹数据收集回来后，怎么用裁剪重要性权重（Clipping）去更新网络梯度”。
  • 自博弈框架（多智能体博弈层）：是 PSRO / Population Self-Play (种群自博弈)。负责回答：“游戏房间里的 4 个人分别由谁来控制？是自己打自己，还是打历史旧版本的模型，还是打不同性格的 AI 种群？”

二、 拆解拆分：它与你常规单智能体 PPO 的 3 大差异

1. 异步采样更新：PPO vs APPO (Asynchronous PPO)

标准 PPO（同步 PPO）是串行的：智能体采样一步 → 等待所有环境走完一个 Batch → 暂停环境 → 用 PPO 计算梯度更新权重 → 将新权重同步回环境 → 继续采样。
但对方是 checkpoints-async（异步更新）：

  • CPU 采样集群（Go 语言引擎）：几百个房间在后台永不停歇地狂跑，持续往数据管道里塞轨迹数据。
  • GPU 训练器（PyTorch）：有数据就取出来算梯度、更权重。
  • 解决策略延迟（Policy Lag）：采样时模型是版本 $V_t$，训练时模型可能已经是 $V_{t+1}$ 了。APPO 会利用类似 V-trace 或 PPO 自带的概率比截断 clamp(r_t, 1-ε, 1+ε) 吸收这种微小的异步误差。

2. 多智能体值函数：PPO vs MAPPO (去中心化执行，中心化评估)

在你的单人 PPO 中，Actor 吐出动作，Critic 评判自己的状态。

而在 2v2 对战游戏中，如果让 Agent 只顾自己，会出现抢队友道具、炸死队友的问题。对方的 Checkpoint 命名为 v253u128-native-team-value-outcome：

  • Team-Value（团队价值函数）：Critic 估算的是整支队伍的胜率 / 期望回报（不仅看自己活没活，看队伍总体是否击杀敌人）。
  • Decentralized Execution（去中心化推理）：虽然训练时 Critic 可以看到全场信息，但部署在实机上的 Actor 依然是单人独立的（每个选手只拿着自己的观测做决策）。

3. 对手从哪里来：Self-Play 与“种群训练 (Population)”

你打单机游戏时，环境规则是固定的（墙就是墙，怪物就是怪物）。但对战游戏里，对手是活人：

  • 纯自己打自己（Naive Self-Play）的死穴：如果房间里的 4 个角色全用同一个最新权重的网络自己打自己，AI 会迅速陷入“剪刀石头布”的局部循环（比如学会了一种特定的堵人套路，结果把之前的基本功给忘了，或者出现全员和平挂机的纳什均衡假死）。
  • 对方用的 Population-based Self-Play（种群自博弈，即 Checkpoint 中标注的 pop-2v2...）：
    1. 系统维护一个历史模型池（Model Pool），存有历史上各个版本的强力模型（甚至不同风格的策略：激进流、控图流、防守流）。
    2. 每开一个新房间，从模型池里随机抽选对手和队友（比如：80% 几率抽最新的自己互打，20% 几率抽历史经典老模型作为考官）。
    3. 这样训练出来的策略不会偏科，既能应对最新学出来的高阶技巧，也不会被初学者的瞎走位打崩（防止策略退化）。
