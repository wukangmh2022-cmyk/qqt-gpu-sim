三、 核心结论与工程启示

1. 为什么我们选择 7.5M Transformer 而非他们这种 CNN+RNN？

对方设计于低算力 CPU 游戏服务器运行，因此必须用人工先验（BFS、反事实避难特征、残差门控）来弥补模型表征能力的不足。而我们面向超大规模 GPU/DCU/910B 现代异构集群，端到端 Transformer 拥有更强的一般性表征能力与 Scaling Law 潜力，无需维护复杂脆弱的启发式代码即可自发学会长程封路与战术博弈。

2. 对方架构有哪些值得我们吸收的地方？

  • 道具与动作空间扩展：如果我们未来需要引入原版全套道具（解救针、飞镖、变身药水），可以参考对方将组合动作映射为扩展离散空间的做法。
  • 战术安全反事实先验 (Tactical Counterfactuals)：在训练初期，可以考虑将对方的“放泡后自身是否有安全避难所”作为辅助监督信号（Auxiliary Loss）或特征加入，能极大加速模型度过初期“自己炸死自己”的试错瓶颈。
