一、 训练算法与运行环境深入证据链

1. 训练架构与软硬件底座

  • 模型 Checkpoint 原身：在 qqtang-rule1.onnx.json 中明确记录来源为：
    "checkpoint": "checkpoints-async/v253u128-native-team-value-outcome-v255/update-000032.pt"
    后缀 .pt 说明模型在 Python 端完全由 PyTorch 构建与训练，最终通过 torch.onnx.export 转出为 qqtang-rule1.onnx。
  • 训练采集架构（Asynchronous Actor-Learner）： 目录名为 checkpoints-async，且环境暴露了 ReuseTensorBuffers 锁页流式接口。这表明采用了 Actor-Learner 解耦的异步强化学习框架（类似 DeepMind SEED RL 或 Ray/RLlib APPO/IMPALA 架构）：
    • CPU 采样集群 (Actors)：利用 Go 编写的高性能多线程引擎（internal/game/battleenv/batch.go 中的 WorkerCount 与 sync.Pool）并发跑几百个无头环境实例，高速产出 TensorBatch。
    • GPU 训练器 (Learner)：PyTorch 异步收集轨迹张量，计算梯度并定期写入 update-0000XX.pt，同时将最新权重广播给采样工作进程。

2. 人类数据使用情况：确定为 0% 人类数据

  • 无模仿学习痕迹：在整个项目中没有任何 imitation、behavioral_cloning、human_demonstration、专家轨迹回放解析等依赖。
  • 全部依赖自博弈 (Self-Play)： 旧版模型路径 pop-2v2-context-deployment-v8-g000-deterministic-selfplay 直接写明了 selfplay（自博弈种群训练）。
  • 环境冷启动全靠精心设计的“强化学习课程 (Curriculums)”： 炸弹人游戏如果直接冷启动自博弈，智能体会陷入自杀和漫无目的乱逛。作者通过在 batch.go 中手工构建了 6 大合成课程（微型训练关卡），让智能体在特定场景下纯通过奖励探索成长：
    • BombEscapeCurriculum：起手脚下直接刷雷，强迫学习躲雷逃生。
    • DevelopmentCurriculum：出生在藏有道具的软墙旁，引导破坏与吃道具。
    • BlockadeCurriculum：双方出生在狭窄走廊两端，训练卡位与封路。
    • ChainFinisherCurriculum：预埋连环泡阵，训练连环爆破与终结技巧。
    • DuelCurriculum：直接进入清空障碍的 1v1 残局，学习残局对抗。
    • LateDuelReplay：捕获普通局中打到决胜阶段的真实状态进行反复微调。

3. 强化学习算法本质：On-Policy 还是 Off-Policy？

特性 判定结果 技术论据
基础算法族 Policy Gradient / Actor-Critic 在代码多处（如 batch.go:41）直接注明 "makes rare endgame blockade states frequent enough for policy-gradient training"，且输出层为包含 Logits 与对应价值网络的典型 Actor-Critic 结构。
数据时效性属性 Near On-Policy (近似同策略) • 不是纯 DQN / SAC / TD3 类带巨大重放缓冲区（Replay Buffer）的典型 Off-Policy。
• 因为模型包含 全局 Recurrent Memory (Hidden=256)，长序列循环神经网络在强 Off-Policy（大时序偏移旧数据）下极易发散，必须采用维持截断时序 BPTT 的同策略或轻微异策略算法。
• 目录名 checkpoints-async 表明采样与训练是异步并发的，采样到的样本策略与训练步有 1~2 步的小幅策略延迟（Policy Lag），通常配合类似 APPO (Asynchronous PPO) 或 IMPALA (带有 V-trace 权重修正) 来解决轻微异策略问题。
