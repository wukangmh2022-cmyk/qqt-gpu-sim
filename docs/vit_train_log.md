# ViT 模型专项训练记录

> QQ堂 13×15 标准关卡 · transformer(ViT) 自对弈与多态联赛 PPO · DCU 集群
> 本文档沉淀：全四轮迭代的参数设置与原因、踩过的坑、现代评测标准、监控 checklist。
> 配套代码：`jax_bomb/`（训练）`scripts/eval_headless_parallel.js`（并行无头评测）`scripts/analyze_maps.py`（地图统计/课程）。

## 0. 模型与训练基线（不变项）

- 架构：`--arch transformer --embed 392 --depth 4 --patch 4 --heads 4 --ff-factor 4` ≈ 7,461,336 参数
- 观测：14×13×15（**14 通道** JAX 视角，2026-08-19 起 ch13=可推箱；第一轮为
  13 通道，旧 ckpt 不兼容）+ 24 维 state token（`encodeObsJAX`/`encodeStateJAX`）
- 环境：241 张 QQ堂标准图（13×15），`levels.json`；`--num-envs 16384 --num-steps 256 --minibatch 16384 --epochs 2`
- 步数口径：8 卡 16384 envs → 8.39M 步/iter；全局 260B 步是总训练量（论文 Average Joe 同量级）
- PPO：`--gamma 0.995 --lam 0.95 --clip-eps 0.2 --vf-coef 0.5 --ent-coef 0.01`
- 奖励常量：`HIT_REWARD 1.5 / STEP_PENALTY 0.001 / WIN_BONUS 10`（jax_train.py）
- 稠密奖励口径（jax_train.py collect_rollout）：掉血 -1.5 = 对方命中 +1.5（**守恒**），每 tick 步罚 -0.001，终局击杀 ±10，超时按血差 × EXPLORE_COEF

## 1. 第一轮迭代（试水，2026-08-20 ~ 21）：500 iter / 4.2B 步

### 1.1 参数
- 无探索/无炸墙塑形（只有 crate 奖励 0.5，退火 30B 步——本轮中途把原 500M 退火改为 30B）
- `train_8gpu_20260820_180405.log`：iter 500/500，155,437 sps，53.97s/iter，loss 收敛 ~-0.007（负值是 PPO 正常形态，见 §5.1）

### 1.2 结果（headless 复测）
| ckpt | 探索率 | 放炮/局 | 炸墙/局 | 吃箱/局 | 隔离图放炮 |
|---|---|---|---|---|---|
| it68 | 6% | 6 | 1.3 | 1.4 | **0** |
| it102 | 4% | **0** | **0** | 0.1 | **0** |
| it204 | 8% | 9 | 3.8 | 2.3 | 3 |
| it340 | 8% | 11 | 4.9 | 2.3 | 4 |
| it500 | **10%** | **16** | **7.1** | **3.3** | **8** |

- 进化方向健康（放炮/炸墙/吃箱持续涨），但**探索率全线 3-10%**（走不到 20 格/195）
- 交叉对打（ckpt vs ckpt）**100% 平局**：400-1800 tick 内打不死对方，命中率仅 0.2-0.9/局
- 空场景对打能决出胜负：68 vs 500 = 20%/80%；500 vs 旧 MLP(5.95B) = 33%/67% —— 进化存在但极慢
- vs Hunter（规则 AI）：全部 ≤11% 胜率（Hunter 纸面太强，不适合做区分度评估基准，只做对抗压力参考）

### 1.3 结论（驱动第二轮设计）
1. **踱步是普遍现象**（不是个别地图）：出生点 3 格处放炮 0/局 → 冷启动死锁（见 §5.3）
2. **炸墙没学会**：crate 奖励给的是"吃到箱子"（+0.5），不是"炸墙"（见 §5.4）
3. **训练量不足**：4.2B 步 = 260B 的 1.6%，进化方向对，速度慢
4. **it102 出现能力退化**（放炮 6→0）：早期训练不稳定，需监控（见 §5.6）
5. **需要**：探索奖励 + 炸墙奖励 + 课程 + 动态退火（第二轮全部落地）

## 2. 第二轮迭代（260B 完整训练，设计定稿）

### 2.1 决定：从头训（--fresh），不接续 ckpt_00000500
原因：
- 配置大改（+探索 +炸墙 +课程），接续有分布偏移残留
- 4.2B 步只占 260B 的 1.6%，"保留基础"收益小（基础链条 it204 后才成形，从头+塑形更快）
- cfg 校验对新字段不兼容（旧 ckpt 无 explore/brick 字段 → 校验拒绝），接续需放宽有风险
- 论文路径（Average Joe）就是从头 + 课程 + 260B

### 2.2 奖励塑形（统一乘动态退火 α）
| 塑形 | 参数 | 为什么 |
|---|---|---|
| crate 吃箱 | `--crate-reward-coef 0.5` | 成长链条 bootstrap（已有） |
| 探索 novelty | `--explore-reward-coef 0.01` | 每 tick 新格 +0.01（visited 掩码，done 清零，单局封顶 0.01×195≈1.95 << 胜负 10）；治踱步 |
| **炸墙** | `--brick-reward-coef 0.05` | 每炸一块砖双方各 +0.025——crate 链路（炸→掷爆率→吃到）太长太弱，PPO 学不会；给"炸墙"即时正反馈打破死锁 |

### 2.3 动态退火（代替固定步数拍脑袋）
```
α = α_fix × α_dyn = max(0, 1 − gs/30B) × max(0, 1 − tanh(k·每局击杀率))
```
- `--reward-anneal-k 1.2`（Pommerman 论文 α=1-tanh(k·x) 同款）
- x = 训练内每局击杀率（collect_rollout 的 kills 统计，日志 `kill=` 列）
- **击杀率上来（会打架了）→ 塑形自动归零 → 只剩纯胜负**；α_fix 30B 兜底（防击杀率长期停滞）
- 日志新增 `kill=X.XXX α=0.XX`，监控退火进度

### 2.4 课程：**最终决定不启用**（260B 全图均匀采样）
地图统计（scripts/analyze_maps.py）：**239/241 张真实图出生点被墙砖完全隔开**（无一张"出生点可通"），room（出生点房间大小）1-4 为主，21 张符合 Pommerman 式起点（room=4 即 2×2 房间 + 出生点距离≤4）。开训前全面砍掉步数门控课程，直接依赖 explore/brick/crate 三路稠密奖励打通全局梯度。

### 2.5 推箱子玩法（2026-08-19 加入，JAX ↔ Web 等效实现）
数据：123/241 张图含可推箱，全部是 1×1 单格箱。
- 观测通道升级：**N_OBS_CH 13 → 14**，ch13 = pushable 二值通道。
- 机制：前缘格判定对齐 Web，每 tick 推 +0.1s，累计 ≥0.3s（3 tick）移一格，格级计时保留。
- 索引安全：JAX 写入一律采用 2D 索引 `.at[pr, pc]`，消除 1D 索引静默 clamp 缺陷。

## 3. 第三轮迭代（48 卡 HL-Gauss / Top-25% / Patch 3 改造，2026-08-29）

### 3.1 改造背景与核心配置
为打破标量 Critic 价值估计饱和与长程归因模糊，启动 24 机 × 2 卡 = 48 卡主训练，引入 P0 系列改造：
- **零和生命演进奖励**：废除人工碎步奖励，采用对局生命差比值 `r = (造成伤害 − 受到伤害) / 5`。
- **HL-Gauss 分布式价值头**：标量 Critic 改造为 128 桶分类头（量程 `[-20, 20]`，标准差 `σ=1.5`，交叉熵损失优化），提升复杂博弈局面的价值区分度。
- **优势过滤机制**：引入 Top-25% 优势度过滤（`adv_top_frac=0.25`）与批内标准化。
- **空间 Token 细化**：探索 Patch 4 改为 Patch 3（单图展开为 25 个 Patch Token）。
- **通信同步**：多机采用 Local SGD K=32，16 副本实测吞吐达到 570,323 SPS。

### 3.2 训练现象与关键教训
- 空场景下模型展现极强压制力（AI Hunter / 空场景 127 胜 0 负 1 平局）。
- **全量 Top-25% 样本过滤导致保守化陷阱**：训练中后段对战局长显著变长、击杀率下降。排查发现，若 Actor 与 Critic 同时只取 Top-25% 高优势样本，会导致价值网络对平庸或防守局面的评估严重失真，诱发策略过度保守。后续修正方案必须锁定为：**Actor 取 Top-25% 高价值样本更新，Critic 保持全量均匀采样拟合**。

## 4. 第四阶段迭代（破局宗师与全能泛化训练，2026-09）

### 4.1 纳什对峙陷阱与评测口径定型
在百亿步深水区高水平纯自博弈中，双方避险微操高度对称，主动在开阔地放泡自伤风险过高，博弈塌缩为“安全距离外静止发呆”的纳什对峙死锁（放泡骤降至 2.3 颗/局，对峙发呆率达 48.6%）。
为消除统计口径歧义，正式确立三大评测域：
- **Domain A（关卡池自博弈）**：241 张全量障碍地图，检验全图开路与吃道具发育。
- **Domain B（核心目标基准）**：空场景 vs 静止靶（Static Dummy）。终极验收红线：击杀胜率 ≥95%、自杀率 ≤2%、无发呆发楞。
- **Domain C（防守压力基准）**：空场景 vs 高频猎人（AI Hunter），检验极限规避与火力反击。

### 4.2 破局组合拳方案
1. **多态联赛对手池（Sparring Pool）**：废除纯镜像自博弈，混入逃跑怪（Flee Bot）、漫游怪（Roam Bot）、静态木桩（Dummy）与历史快照，彻底打破对称僵持。
2. **初始血量域随机化**：引入 40% 1-HP 生死局 + 30% 2~3 HP 快节奏死斗 + 15% 逆境非对称血量，单次命中直接定胜负，强行逼出开阔地连环下泡闪电终结能力。
3. **纯净梯度屏蔽（mask_bot_advantages）**：混入规则 Bot 时，反向传播将 Bot 席位优势度强制置零，Top-k 过滤将 Bot 权重视为负无穷（-1e9），保证网络 100% 仅从 AI 主动追猎样本汲取梯度。
4. **属性守恒散落与发育底噪**：保留开荒底噪（crate_floor=0.10），配合掉血扣 2 层补 2 箱守恒散落，彻底解决百亿步深水区吃道具发育本能遗忘。

### 4.3 终局战果与标杆模型
- 标杆模型：`params_it00000831_ema`（24 卡集群百亿步收敛产物）。
- 战绩表现：空旷场景下实现极限连泡截杀、四向闭环合围、瞬爆绝杀；复杂 241 地图下兼备推箱开荒与伏击破局，彻底突破纯自博弈对峙死锁。

## 5. 踩过的坑（按时间线深度复盘）

### 5.1 负 loss 不是 bug（易误判）
分类任务 loss ≥ 0；PPO 的 loss = pol(advantage 加权，正 advantage 时负) + vf(≥0) − ent(恒负)。收敛后 loss 稳定在 -0.006~-0.001 是**熵项贡献的正常形态**。判别标准：NaN/Inf 才是问题；rew/explore/ep_len 健康即可。外行人容易误报，切勿盲目停训。

### 5.2 退火窗口拍脑袋会翻车（第一轮最大教训）
原 crate 退火 500M 步（≈1 小时）→ 训练到 2.3B 步时塑形早已归零，模型还没学会。改为 30B 全覆盖 + 动态击杀率退火。**教训：退火窗口必须 > 预期学习周期，或完全动态化**。

### 5.3 冷启动死锁：为什么出生点 3 格"一个炮都不敢放"
- 随机初始化确实会尝试放炮；但放炮即时期望回报为负（炸不到隔离的对方 + 可能自伤 -1.5 + 炸墙大概率无箱 0 奖励）。
- PPO 快速收敛到"不放炮"（踱步 = 安全局部最优），ent_coef=0.01 太小不再随机尝试导致困死。
- **解法**：探索奖励（动起来有分）+ 炸墙奖励（破墙有分）打破冷启动死锁。

### 5.4 crate 奖励 ≠ 炸墙奖励
`crate_coef` 只在"吃到箱子"（站在箱子上）给分。完整链路 放炮→引信 30 tick→炸→掷爆率(0.5-0.8)→走过去→吃到 → +0.5，任何一环断就 0 奖励，PPO 信用分配极差导致开荒失败。**教训：链路型奖励学不会时，必须给中间环节即时正反馈**。

### 5.5 位置偏置（P0 强 P1 弱）是"镜像同步"假象
同权重自博弈 self 对打中 P0 位置胜率常偏高，排查确认是同权重 + 对称观测诱发的**镜像同步竞争**（同格放泡 P0 优先结算）。异权重互打（cross）完全无偏置，证明模型本身无视角缺陷，训练端无需人工交替身份。

### 5.6 it102 能力退化（早期探索震荡）
self 对打中 it68→it102 曾出现放炮与炸墙归零（it204 恢复）。本质是早期价值函数与 GAE 优势估计剧烈震荡所致，训练深水区需严密监控价值网络损失分布。

### 5.7 Hunter 不适合做唯一胜率基准
手写规则 Hunter 具备高频进攻寻路，纸面压迫极高。**评估模型相对强度应以 Checkpoint 互打（cross）与静止木桩击杀基准（Domain B）为核心**，Hunter 仅作为对抗压力下的避险身法参考。

### 5.8 levels.py 课程权重数值陷阱
- 浮点累加略微超 1 导致未指定地图权重出现微小负数，`np.log(负)=nan` 毒化采样。修复：对剩余权重显式 clamp。
- 全图均指定采样时除零。修复：直接防御性返回。

### 5.9 LSGD 大 Batch 优化器动力学滞后
在 `LSGD_MODE=grad (K=32)` 下，单轮 Adam 参数更新频次减少 32 倍，有效 Batch 膨胀 32 倍。在固定学习率下，策略在参数空间中单轮行进的欧氏距离被压缩，导致脱离低熵对峙鞍点的时间显著滞后。生产必须配合充分的训练步数（百亿步级）与适当动量补偿。

### 5.10 手术改参割裂动作头协同（反面教训）
曾尝试通过“参数手术”强行将放泡头偏置修改为正向（b=+0.2），虽瞬时提高放炮率，但因破坏了移动规划网络与放泡网络在时序上的精密协同，导致在静止靶测试中自杀率暴增至 80%，胜率跌至 5%。动作协同必须依靠端到端强化学习自博弈联合演进，严禁脱节干预。

### 5.11 评测基准失真陷阱
早期基于单机 JAX 的简化评测对局上限仅 800 tick，且规则对手无避险寻路，产生了 100% 胜率的虚假繁荣。一旦切换到前端真实物理（1800 tick 满帧、0.3s 余威伤害、完整多源 Dijkstra 避险），真实胜率直接暴露。评测基准必须与真实部署环境完全对拍。

## 6. 现代无头对战评估方法（eval_headless_parallel.js）

官方基准评测已统一收敛至多进程并行评测套件，采用与网页端完全一致的真物理引擎（含 1800 tick 上限、0.3s 余威扩散、残骸延迟阻挡与 Dijkstra 避险寻路）：

```bash
# 标准验收基准：4 进程并发，128 局（4 场景 × 32 局，耗时约 3 分钟）
node scripts/eval_headless_parallel.js --workers 4 --games 32

# 生产级高密度大考：512 局全量基准（4 场景 × 128 局，耗时约 12 分钟）
node scripts/eval_headless_parallel.js --workers 4 --games 128
```

评测涵盖四大权威场景：
1. `AI Hunter / 空场景道场`：对战高频进攻猎人
2. `AI Hunter / 全池 241 复杂地图`：全地形掩体实战
3. `静止木桩 / 空场景道场`：基准击杀与身法协同（通过线：100% 胜率、0 自杀）
4. `静止木桩 / 全池 241 复杂地图`：全图开荒与长程迷宫寻路

## 7. 监控 checklist（生产训练）

### 7.1 每 iter（日志行）
- `sps` ≈ 16 万至 46 万量级；骤降 = 节点异常
- `loss` 负值正常（§5.1），NaN/Inf = 立即停训排查
- `explore=X.XXX` 探索分/帧（应早期上升、随 α 正常退火）
- `kill=X.XXX` 每局击杀率（动态退火联动指标，应稳健爬升）
- `α=0.XX` 塑形总退火系数
- `rew`、`ep_len`（1800 tick 上限）

### 7.2 周期性与里程碑
- ckpt 落盘（`ckpt_<iter>_r0.pkl`）；rank0 周期参数轻量快照（`params_it*.pkl`）
- 无 Traceback/Error/Exception
- 定期拉回参数快照跑 `eval_headless_parallel.js`，严格以 Domain B 静止木桩 100% 胜率与低自杀率作为第一道验收门禁
